# Unity 2D 不规则地形 · 三条路线

配套代码。针对"想要一个像 PolygonCollider2D 那样能直接拖边缘的地形组件"这个需求。

**所在项目**：OrisLevel（Unity 2022.3.53f1 · URP 14 · 2D Renderer）

**命名**：命名空间是 `LDK2D` / `LDK2D.EditorTools`，所有类型和文件都带 `LDK2D` 前缀
（`LDK2DHeightmapTerrain`、`LDK2DPolygonMesh` …），装进别的项目不会和已有类型撞名。
菜单在 `GameObject ▸ LDK2D ▸ …`。
**例外**：`EditorPrefs` 的键和目录名仍是旧的 `Terrain2D.*` / `Assets/Terrain2D/` ——
键是字符串不产生编译冲突，改了会丢已存的 Z 预设和调色板。

```

├── Scripts/

│   ├── LDK2DPolygonMesh.cs            ★ 轮廓 → Mesh，轮廓来自 PolygonCollider2D
```

依赖：`com.unity.feature.2d`（已装，含 Sprite Shape 9.0.5 / Tilemap Extras 3.1.3）、
`com.unity.modules.physics2d`。没有额外的第三方依赖。

**快速上手**：菜单栏 `GameObject → LDK2D → 创建高度场地形` 直接生成一块地形，
再 `GameObject → LDK2D → 创建测试角色` 加一个能跑能跳的方块（顺带把跟随镜头配好），
按 Play 就能试地形。
另一个菜单项 `GameObject → LDK2D → 为选中的碰撞体添加多边形网格` 给已有的
`PolygonCollider2D` 补上渲染。

**Inspector 字段标题、悬停提示、按钮、菜单全部是中文的。**

字段标题的中文写在 `Editor/LDK2DInspectorL10n.cs` 配合各编辑器里；
悬停提示直接反射读取组件字段上的 `[Tooltip]`，所以文案只有一份，改一处即可。

## 改颜色

两个组件都有独立的「外观」分组，直接改 **颜色** 字段即可，不用去动材质：

| 字段 | 说明 |
|---|---|
| 颜色 | 只作用于**当前这个物体**，改完立刻生效 |
| 应用颜色 | 关掉后不再自动刷颜色，完全手动控制 |
| 排序层 | 2D 排序层，默认 `Default` |
| 排序顺序 | 数值越大越靠前（越靠镜头） |
| UV 缩放 | `1 / UV 缩放` = 贴图重复一次所跨的世界距离 |
| UV 模式 | 平面映射 / 沿曲面平铺，见下面「资源替换」 |
| 显示 UV 网格 | Scene 视图里标出贴图接缝的位置 |
| 翻转绕序 | 材质开了背面剔除导致看不见时打开 |

> **为什么改一个颜色不会影响其他物体？**
>
> 颜色走的是 `MaterialPropertyBlock`（逐渲染器的覆盖值），**不是**写进 Material 对象。
>
> 早先的写法是 `renderer.sharedMaterial.SetColor(...)` —— 那是写材质本身。
> 而 `EnsureMaterial` 自动挂的是"内嵌材质"（不是项目里的材质资产），
> 复制物体、或者同一个 prefab 的多个实例，会指向**同一个 Material 对象** ——
> 于是改一个颜色，所有共用它的物体一起变。
>
> 换成 MaterialPropertyBlock 之后：不碰材质对象、不实例化新材质，天生每个物体一份。
> 颜色本身存在组件的 `color` 字段里（会序列化），每次 `OnEnable` / 重建都会重刷一遍，
> 所以不依赖 block 自己被保存。
>
> 代价：带 MaterialPropertyBlock 的渲染器会跳出 SRP Batcher。地形物体数量不多，
> 可以忽略。

## 路线 A：Sprite Shape（官方内置，不需要任何脚本）

**这就是你要的"能拖边缘的地形组件"。**

1. `Create → 2D → Sprite Shape Profile`，类型选 **Open**。
2. Profile 里配 Sprite 列表和 **Angle Range**（哪个图负责平地、斜坡、陡坡）。
3. 把 Profile 拖进场景 → 生成带 `Sprite Shape Controller` 的物体。
4. 在 Controller 上点 **Edit Spline**，控制点就出来了。拖动 = 改地形边缘。
   - 选中点按 **M** 切换 Linear / Mirrored / Non-Mirrored
   - 点曲线中间可以加点，按 **Del** 删点
   - 按住拖动出曲线，Linear 模式出硬角
5. **加碰撞体**：给同一个物体加 `Polygon Collider 2D` 或 `Edge Collider 2D`，
   Controller 上会多出一个 **Collider** 折叠区：

| 属性 | 作用 |
|---|---|
| Update Collider | 默认开。地形一改，碰撞体自动跟着更新 |
| Offset | -0.5 ~ 0.5。把碰撞边缘从视觉边缘推出去/收进来 |
| Optimize Collider | 默认开。自动清理共线的多余点 |
| Detail | 碰撞体的细分质量 |

关键点：**`Update Collider` 打开时，你手改的碰撞体顶点会被覆盖**。
想手动微调碰撞形状，就把 `Update Collider` 和 `Optimize Collider` 都关掉。

> 细节：Sprite Shape 的渲染 Mesh 是内部生成的，没有公开 API。碰撞体走的是上面这套机制，
> 所以不需要写脚本，也别去尝试读它的 mesh。

## 路线 B：LDK2DPolygonMesh（任意多边形，四条边都能加点）

`PolygonCollider2D` 就是那个"可以自定义边缘"的组件，只是它不负责渲染。
`LDK2DPolygonMesh` 补上渲染这一半：**读碰撞体的 path → 三角化 → 生成 Mesh**。

**需要左右边也能加点编辑、需要斜边、需要隧道/洞穴 —— 就用这条路线。**
它是自由多边形，没有"哪条边不能编辑"的限制。

工作流：

1. 建一个空物体，加 `Polygon Collider 2D`。
2. 加 `LDK2DPolygonMesh`（`MeshFilter` / `MeshRenderer` 会自动补上）。
3. 选中 `Polygon Collider 2D`，点 **Edit Collider** 进入编辑状态。
4. 在 Scene 视图里操作：

| 操作 | 效果 |
|---|---|
| 拖动锚点 | 移动顶点 |
| **Shift + 点边线** | 在该处**插入一个顶点** |
| **Ctrl / Cmd + 点锚点** | **删除**该顶点（至少保留 3 个） |

5. 改完立刻看到填充好的地形。`实时更新` 默认开，靠比对顶点哈希来触发重建，开销很小。

> **锚点加不上？** 检查物体的 Scale。Unity 的碰撞体编辑器在 Scale 过大时会失效，
> 这是已知问题，把 Scale 设成 1 就好。

**和路线 C 的分工**

| | LDK2DHeightmapTerrain | LDK2DPolygonMesh |
|---|---|---|
| 形状 | 地表 + 底部两条曲线（带子） | 任意闭合多边形 |
| 左右边 | 只能是直线（可用青色手柄拖成斜线） | 任意曲线，可加点 |
| 洞 / 隧道 | 不支持 | 支持（keyhole 画法） |
| 噪声生成 | 支持 | 不支持 |
| 可破坏 | 支持（改数组） | 不支持 |
| 编辑方式 | 本工具自带编辑模式 | Unity 的 Edit Collider |

**要点**

- 碰撞体的每一条 path 会变成一个独立的填充区域，彼此是"岛"不是"洞"。
- 要挖洞，用 **keyhole** 画法：从外轮廓切一条很窄的缝进去，绕洞一圈再缝回来，
  这样整体仍是一个简单多边形。见 `LDK2DTriangulator` 注释。
- 顶点顺序（顺/逆时针）不用管，内部会归一化。
- 没指定材质时自动挂 URP 2D 着色器（`Sprite-Lit-Default` → `Sprite-Unlit-Default` → `Sprites/Default` 依次尝试）。
  渲染反面了就把「翻转绕序」打开。

**Inspector 参数（中文）**

| 参数 | 说明 |
|---|---|
| 轮廓来源 | 「多边形碰撞体 2D」或「本地顶点列表」 |
| 轮廓 | 读哪个碰撞体，留空则找自己身上的 |
| 颜色 / 应用颜色 | 见上面「改颜色」 |
| 排序层 / 排序顺序 | 2D 图层排序 |
| UV 缩放 | 平面 UV，`localX × uvScale` |
| Z 偏移 | 网格的 Z 偏移，用来分层 |
| 翻转绕序 | 材质开了背面剔除时用 |
| 实时更新 | 轮廓变化时自动重建 |

**API**

```csharp
var mesh = GetComponent<LDK2DPolygonMesh>();
mesh.Rebuild();                          // 手动重建
var paths = mesh.ReadPaths();            // 读当前轮廓（局部坐标）
```

## 路线 C：LDK2DHeightmapTerrain（不规则地形 / 程序化 / 可破坏）

地形是**一条闭合折线围成的实体**，四条边都能加点：

```
地表曲线（左→右） → 右边链 → 底部曲线（右→左） → 左边链
```

- `Heights[]` = 地表高度
- `BottomHeights[]` = 底部轮廓（关闭「底部独立轮廓」时退化成一条平直线）
- `LeftEdge` / `RightEdge` = 左右两条边上的控制点（默认空 = 直线）

网格和碰撞体都从这条闭合折线派生。因为地表是"X 的函数"，挖洞只是改数组里的数字。

**不能做的**：地形中间挖洞（隧道、洞穴）—— 单条闭合折线表达不了"环"。
那种需求用 `LDK2DPolygonMesh`。

**Inspector 参数（中文，按分组排列）**

| 分组 / 参数 | 建议值 |
|---|---|
| **形状** · 采样点数量 | 128 ~ 512 |
| **形状** · 采样间距 | 0.25（世界单位/采样） |
| **形状** · 起始 X | 0 |
| **形状** · 底部独立轮廓 | 做不规则地形时打开 |
| **形状** · 底部 Y | 底部平直时的高度（开启独立轮廓后只作初始值） |
| **形状** · 底部左/右端点水平偏移 | 拖成斜边用（开启独立轮廓后才显示） |
| **程序化生成** · 随机种子 | 固定种子 = 可复现 |
| **程序化生成** · 起伏幅度 | 3 |
| **程序化生成** · 噪声频率 | 0.02 ~ 0.1（越小山越宽） |
| **程序化生成** · 叠加层数 | 4 |
| **程序化生成** · 幅度衰减 | 0.5 |
| **程序化生成** · 平滑遍数 | 2（0 = 原始噪声） |
| **外观** · 颜色 | 见上面「改颜色」 |
| **碰撞** · 生成碰撞体 | 默认开。整块实心，从任何方向都挡 |
| **碰撞** · 碰撞体采样间隔 | 1（只有地形极长时才调大） |

**编辑模式（相当于 PolygonCollider2D 的 Edit Collider）**

Inspector 底部有 **「进入编辑模式」** 按钮，点一下进入（再点退出）。
编辑模式在 Scene 视图里的操作：

| 操作 | 效果 |
|---|---|
| 拖**蓝色**圆点 | 改**地表点**（自由 2D：上下改高度，左右改水平偏移） |
| 拖**紫色**圆点 | 改**底部点**（自由 2D，需要打开「底部独立轮廓」） |
| 拖**橙色**圆点 | 改**左 / 右边**上的控制点（自由 2D） |
| **Shift + 点任意一条边** | 在该处**插入一个控制点**（四条边都行） |
| **Ctrl / Cmd + 点圆点** | **删除**该控制点 |
| 拖**绿色方块**（左右边中点） | **移动左 / 右边界**，对侧固定不动 |
| 拖**青色方块**（底部左右角外侧） | **把左 / 右边拖成斜线**（需要打开底部轮廓） |
| 拖**橙色方块**（底边中点） | 改**底边整体高度**（关闭底部轮廓时才有） |

**所有圆点都是自由 2D 拖动**：横向移动会记进该点自己的水平偏移里，只影响它自己。

采样点的 X = `originX + 下标 × spacing + 该点的水平偏移`。默认偏移全是 0，也就是均匀分布。
横向拖歪了想重来，点工具栏的「**清空横向**」。

进入编辑模式后：
- Scene 视图会画出**完整闭合轮廓**（地表亮橙 + 底部紫色，四条边都在里面）
- 显示**全部**采样点（不再受「控制点间隔」限制），控制点缩小一号避免挡住
- 按住 Ctrl 时圆点变红，表示进入删除态（此时不显示边界方块，免得误抓）

### 视口的两个角

工具分成两块，各占一个角，职责不重叠：

```
┌─ 左上角：阶段面板 ─────────────┐                        ┌────────────────┐
│ ▾ 搭建              地表 29    │                        │  Unity 自带的   │
│ 颜色 [■]▾                      │                        │  竖排工具条     │
│ [边界方块][平滑拖动]           │                        │  （避开它）     │
│ 层级 [0]  Z [0]▾               │                        └────────────────┘
│ [碰撞体]      层级大在上       │
│ [生成][拍平][重建]             │
│ [细分 ×2][简化一半]            │
│ [清空边加点][清空横向]         │
│ ■地表 ■底部 ■边点              │
│ ■移边界 ■边变斜 ■底边整体      │
└────────────────────────────────┘

┌──────────────────────────────────────────┐
│ 关卡设计  [ 搭建 ][ 测试 ][ 资产替换 ]   │   ← 左下角：固定栏
└──────────────────────────────────────────┘
```

| 位置 | 内容 | 什么时候在 |
|---|---|---|
| **左下角 · 固定栏** | 关卡设计 + 三段选择器 | **永远在** |
| **左上角 · 阶段面板** | 当前阶段的工具 | 永远在，内容随选择变 |

**为什么选择器单独放左下角**：它回答的是"这块关卡走到哪一步了"，和选中什么无关。
放进面板的话，取消选择时它会跟着消失 —— 而这恰好是你在看整张关卡、最需要知道
进度的时候。面板里**故意不放**选择器：面板的内容随选择变，阶段不该跟着变。

**面板标题行**写的是阶段名 + 一个关键数字，因为选择器在视口另一端，
收起面板之后光看内容分不清现在是哪个阶段。折叠状态是全局的
（`SessionState` 的 `Terrain2D.PanelOpen`），不按物体记。

**阶段是全局的，不是每个地形一份。** 场景里放三块地形，选中哪块都不该把阶段重置。
存在 `EditorPrefs` 的 `Terrain2D.Stage` 里，所以关掉 Unity 再打开还在那个阶段。

**什么都没选时**，面板里只放这个阶段"最想做的第一件事"：

| 阶段 | 面板里的动作 |
|---|---|
| **搭建** | [创建高度场地形] |
| **测试** | 先选摄像机模式，再 [创建测试角色（跟随）]，然后 [ ] 实时编辑，最后三行占位标记：敌人 / NPC / 奖励点 |
| **资产替换** | 一句提示 + **场景显示层级**（指定 Z，开关这一层）+ 显示碰撞体 |

**「实时编辑」是 Play 模式的开关**：勾上之后，Play 里拖地形点、改参数、摆敌人，
退出 Play 时这些改动会写回场景；不勾就是纯跑图，Play 里连地形手柄都不画。
详见下面「实时编辑」一节。

占位标记在**选中地形**和**什么都没选**两种状态下都出现 —— 搭关卡时人经常什么都不选，
要是非得先点一块地形才能造敌人，这个入口就白放了。

**选中非地形的 2D 物体时**，面板显示层级 / Z / 颜色 / 碰撞体 —— 这些是"这个物体"的
属性，和阶段无关，所以三种阶段下都一样。

碰撞体那一格是**一颗开关**：勾上就补上缺的 `BoxCollider2D` 并全部启用，取消只
`enabled = false`、**不删组件** —— 和地形层的开关是同一个逻辑。多选时只要有一个物体
身上没碰撞体，开关就显示为关，点一下全补上。

**资产替换阶段（什么都没选时）多了「场景显示层级」**：给一个 Z，把这个 Z 上的渲染器
统一显示 / 隐藏。Z 有两种给法——输入框直接输（默认 `0`），或者点 `▾` 从 `LDK2DDepthPresets`
里选存过的命名 Z（「地形 (0)」这种），和「层级 / Z」那一行共用同一张预设表。

**只关渲染器，碰撞体一律不动** —— 关掉一层是为了看清下面那层在画什么，如果连碰撞一起
关掉，"我明明关了背景、角色却掉下去了"就会变成常态。

放在**什么都没选**的面板里而不是选中地形那块：它管的是整个场景的显隐，和选中哪块地形
无关；而且人检查整体效果时通常什么都不选。右边的「显示碰撞体」和视口右下角那颗按钮是
**同一个状态**。

阶段状态和选择器的画法在 `Editor/LDK2DTerrainStage.cs`，面板的定位在
`Editor/LDK2DSceneToolbarLayout.cs`（`Panel()` 会避开 Unity 自带的竖排工具条：
那块的高度随 2D/3D 模式变，宽度不变，所以往右让而不是往下让）。

**右下角是一个全局工具箱**（`Editor/LDK2DViewportZoomSlider.cs`），现在装的第一件是
**视口缩放滑条**（宽度 `288px`，第二行要放下标记工具那套东西）。

滚轮缩放**没有刻度**：缩着缩着就不知道自己是放大了还是缩小了，也不知道还能不能再缩出去；
想把整个关卡一眼看全，只能来回滚、靠感觉停。这根滑条把"缩放到哪里"变成一个
可以看见、可以拉回去的值：

| 位置 | 效果 |
|---|---|
| 拉到最右 | **整个场景刚好装下** |
| 拉到最左 | 放到最大，约 25 倍变焦范围 |

"装下全场景"是**算出来的**，不是常量：取所有 `Renderer` 包围盒的并集，
高度和宽度各算一遍取大的（只看高度的话宽扁关卡会左右溢出）。被关掉的渲染器不参与 ——
场景显示层级把某层藏了之后，拉满应该只装下看得见的部分。

拉满时顺手把视图中心对到场景中心，**只对一次**（`_pinned`）。视野够了但中心偏着还是看不全；
每帧都对的话用户拉满之后就没法平移视图了，镜头会被一直拽回去。

滑条值**从 `view.size` 反算**，不另存一份 —— 用滚轮缩放之后滑条必须跟着动，
这才是"等价于滚动缩放"该有的样子。正交和透视要分开换算：正交下 `view.size` 就是半高，
透视下它是相机到焦点的距离，得按 FOV 折算。

左边的**眼睛是标识，不是按钮**（`Label` 不是 `Toggle`/`Button`）。点它不会有任何反应，
也不该有 —— 它只说明这条滑条管的是"视口看得见多大"，跟第二行的标记工具区分开。

**工具箱第二、三行是场景标记**（`Editor/LDK2DMarkupTool.cs`）。摆关卡时最常冒出来的念头是
"这里得补个跳板""这块坡不对"，以前只能靠记忆。现在直接在视口里标：

| 工具 | 怎么用 | 尺寸 |
|---|---|---|
| 笔 | 左键拖，自由画 | 线宽 `1~8` px，可调 |
| 框 | 左键拖出一个矩形，松手直接进标签编辑 | 描边 `2~8` px，随屏幕尺寸自动加粗，**平时无填充** |
| 字 | 点一下，弹出输入框，回车确认 | 字号 14px |
| 擦 | **只擦笔迹，而且只擦圈经过的那一段**。按住拖，一路擦过去 | 半径 8px 的圆 |

四个预设色块是语义：**黄 = 待办、红 = 有问题、青 = 已确认、白 = 备注**。
第五个控件是**色盘** —— 左边是当前色块（点它开取色器），右边是吸管（从视口里吸地形颜色）。
里面是 Unity 自带的取色器：HSV 圆盘 + RGB / 十六进制输入 + 存过的色板，要什么色自己调。

这个控件给 `38px` 而不是 `18px`：`EditorGUI.ColorField(showEyedropper: true)` 是左右排布的，
吸管固定占 `~18px`，剩下的才给色块。给 `18px` 的话色块被压成 0 宽，
界面上只剩一个吸管图标，看着根本不像颜色按钮。
预设留着是因为这四个有语义、点一下就走，不该为了"自由选色"把常用操作变成每次都要开色盘。
用自定义色时那个色块会描一圈白边（四个预设都没亮，得看得出"现在用的是它"）。

**删除分两条路**：笔迹用橡皮点掉；框和文字要点出来，出现 `×` 按钮，再点按钮。

| 对象 | 怎么删 | 怎么改 | 怎么移动 | 怎么缩放 |
|---|---|---|---|---|
| 笔迹 | 橡皮拖过去，圈里的部分消失 | —— | —— | —— |
| 框 | **点描边** → `×` 按钮 → 点按钮 | **双击**，改标签 | 点中描边后按住拖 | 拖**四个角**，对角固定 |
| 文字 | **点文字** → `×` 按钮 → 点按钮 | **双击**，改正文 | 点中后按住拖 | 拖**右下角**，改字号 |

**单击 = 选中，双击 = 改内容。** 单击必须留给"选中 + 接着拖" ——
不然一按住鼠标就进编辑框，根本拖不动。

**缩放手柄是屏幕像素**（`8px` 白方块），不随视口缩放变 —— 缩到全图时还是那么好点。
框拖角时**对角固定**（拖左下角，右上角不动）；文字按**距离比**改字号（`6~96`），
用绝对位移会前半段没反应、后半段猛跳。

**手柄的命中优先级高于"重新选中"** —— `MouseDown` 里先 `TryBeginResize` 再 `TrySelectAt`。
顺序反了的话，想拉大框的时候会先把框重新选中一遍，手柄永远抓不住。

拖动位移按**世界坐标**算，不按屏幕像素：视口缩放时同样的鼠标移动量对应的世界距离
完全不一样，按像素算会在放大后拖不动、缩小后拖飞。删除按钮跟着走，
不然拖完 / 缩完它就留在原地了。

拖动和缩放的 Undo 都**推迟到真的改了才拍**（`_moveUndoPushed` / `_resizeUndoPushed`）——
放在 `MouseDown` 里的话，单纯"点一下选中"也会拍一张快照，
Ctrl+Z 会多出一堆"什么都没变"的步骤。

**橡皮是"剪一段"，不是"删一笔"**（`EraseRadius = 8px` 的圆）。一笔长线中间写错一个字，
不该逼人整条重画。按住拖过去，圈里的部分被剪掉，剩下的按连续段拆成几条新笔迹，
颜色和线宽都跟着走。一次拖动算**一步**撤销。

实现按**线段**算而不是按点算：采点间距是画的时候的屏幕 `2px`，视口放大之后相邻两点
可能隔着几十像素，只删"圈内的点"会整段跳过去 —— 表现就是"擦了半天那一段还在"。
所以对每一段解 `|a + t(b-a) - c|² = r²`，求出圆内的参数区间，只剪区间内的部分。
判定前先用**世界坐标包围盒**粗筛，避免每帧对每个点做 `WorldToGUIPoint`。

框和文字不做成橡皮能擦的，是因为它们不是"画"出来的、是"摆"出来的 ——
手一滑擦掉一个框，里面圈的区域就白标了；擦掉一段文字，那句话就再也想不起来了。

**框只认描边**（容差 6px）：框是"圈区域"用的，大框的内部范围太大，
点里面就选中会把里面的东西全挡掉。删除按钮钉在点中它的那一下的位置正上方，
跟着场景走 —— 视口缩放时不会飘到别处。

**第三行是按类型统一显示 / 隐藏**：`笔画` / `文字` / `框` 三个开关，状态存 `EditorPrefs`。
**不是"一键全关"** —— 三种标记的用途不一样（笔迹记想法、框圈区域、文字写结论），
经常需要"只看框、把笔迹藏起来"，所以分开控制。

**数据在场景里，绘制在 Handles 层。** 场景里只有一个 `_LDK2D_Marks` 对象挂 `LDK2DMarkup`
存三种列表（`strokes` / `texts` / `boxes`），**没有 MeshRenderer、不进 Game 视图、
不参与 URP 2D 管线** —— 视觉上就是浮在场景上面的一层。

三种标记分开存三个列表、不塞进一个多态列表：Unity 的序列化不认多态，
而且"按类型统一显示 / 隐藏"本来就需要能按类型遍历。

不用 `LineRenderer`，是因为它的宽度是**世界单位**：视口缩远了线变发丝、凑近了变马路，
而标记恰恰要跟着视口缩放保持同样的视觉重量。也不用 GUI 层（`GUI.DrawTexture` /
`EditorGUI.DrawRect`），因为 GUI 层只能画矩形，斜线全是锯齿。
`Handles.DrawAAPolyLine` 的抗锯齿是白送的，线宽本来就是屏幕像素。

**框的描边会随缩放变粗**（`2px → 8px`）。描边宽度是屏幕像素，所以视口一缩、
框跟着缩、线却不变粗细 —— 缩到能看全图时框只剩几十像素，2px 几乎看不出形状。
现在按**框自己的屏幕尺寸**插值：短边 `>= 120px` 给 `2px`，`<= 20px` 给 `8px`，中间线性过渡。

为什么不用"视口缩放倍数"当依据：天生画得很小的框，在 1:1 的视口里同样需要粗一点才看得见 ——
该看的是**它现在多大**，不是相机在哪。取宽高里较小的那个，细长条只要有短边撑不住一样看不清。
再兜一层：线宽不超过短边的 `30%`，否则缩到极小时框会糊成一个实心色块、丢掉"这是个框"的信息。

**框为什么平时不填充**：填充会把框里的地形蒙住一层色，而框里恰恰是要看的东西。
框存在的意义是圈出一块区域让人去看，不是把它盖掉。只有点中之后才补一层
`alpha 0.14` 的填充 + 描边提亮，用来确认"选的是这一个"。
描边不用 `DrawSolidRectangleWithOutline` 的 outline 参数，因为那个固定 1px、改不了粗细。

手感的三个具体动作：**采点按屏幕距离**（2px，按世界距离会在放大时点太密、缩小时点太疏）；
**收笔时 Chaikin 细分一轮**把折线抹成弧线；**画的时候 `Event.Use()`**，
不然画一笔顺手把物体全选中了。`Alt + 左键` 放行给视口环绕。

**撤销是整笔退**：`MouseDown` 时拍快照，Ctrl+Z 退掉一整笔。点一下就松手不算一笔。

**Play 模式也能画，退出后标记还在**：`ExitingPlayMode` 把数据抄成 JSON 存进 `SessionState`
（跨域重载也活着），`EnteredEditMode` 再写回场景对象。直接覆盖不合并 ——
Play 场景是编辑模式场景的副本，数据本来就是超集。

> 工具箱额外行通过 `ExtraRow` + `ExtraHeight` 两个静态委托挂进来：
> `LDK2DViewportZoomSlider` 比 `LDK2DMarkupTool` 老，**旧文件引用新类型**会在 Unity
> 增量编译「先编译、后导入」那一轮报 `does not contain a definition`，
> 所以反过来由新文件往旧文件的委托上挂。`ExtraHeight` 单独问一次是因为
> `GUILayout.BeginArea` 的高度必须在**画之前**定下来，画完再问就晚了（给少了会被静默裁掉）。
> 同一原因，工具箱暴露 `ToolboxRect` 让标记判断"这一下点击是不是落在工具箱上"。

轮廓自交时，**警告框会出现在阶段面板的最上面**（红字），不用切到 Inspector 就能看到。


**地形轮廓是一条闭合折线**

```
地表（左→右） → 右边链（上→下） → 底部（右→左） → 左边链（下→上）
```

四条边都是折线，都可以加点。默认左右两条链和底边折线都是空的：

- 左右链空 = 竖直直线
- 底边折线空 = 用 `bottomY` 那条平直线（或开了「底部独立轮廓」之后的逐点数据）

**加点是分边独立的** —— Shift+点哪条边就加在哪条边上，别的边不动。
底边有自己的折线（`BottomEdge`），所以往底边加点**不会碰地表**。

- **没加过边控制点（含底边）、也没横向拖过点** → 走三角带三角化，又快又稳
- **加过边控制点，或有过横向偏移** → 改走耳切三角化，支持任意轮廓

> **轮廓自交会怎样？** 控制点拖过头让轮廓自己交叉时，耳切解不出来，网格会停止更新，
> Inspector 会弹红色提示。把点往回收一点就恢复 —— 这是有意的，比留一个破面好排查。

**做不规则地形（浮空岛 / 悬岩 / 天花板）**

1. 打开「**底部独立轮廓**」——底部会初始化成一条平直线（高度 = 底部 Y）
2. 进编辑模式，拖紫色圆点把底边塑形
3. 底边想要更细的点：**Shift + 点底边** —— 走独立的底边折线，地表完全不受影响
4. 左右边想要更自由的形状：Shift + 点左右边加点，拖橙色圆点做外凸或内凹的岩壁

> 需要**地形中间挖洞**（隧道、洞穴）仍然要用 `LDK2DPolygonMesh` ——
> 单条闭合折线表达不了"环"这种拓扑。

**为什么拖动不用 `Handles.Slider`**

`Handles.Slider` 既负责渲染手柄又负责计算偏移量，在"每帧重建网格"的场景下反馈不稳定
（拖动会跟不上鼠标）。现在改成自己管 `hotControl`，用
`HandleUtility.CalcLineTranslation` 把鼠标位移直接投影到拖动轴上，
得到**相对抓取点的绝对偏移** —— 不累积、不自激，而且手柄能实时跟着鼠标走。

两个批量按钮（只在编辑模式下显示）：

- **细分 ×2** —— 每两点之间插一个新点，点数变成 2n−1
- **简化一半** —— 隔一个取一个，点数约减半

**加点原理**：地形是等距高度场，所以"加点"就是细分——点数变了，
但 `spacing` 会跟着重算，**地形总宽度保持不变**。新点高度取左右邻居平均，轮廓不会跳。
这样 `SampleHeight`、挖坑、碰撞体全都不用改。两端点不能删，它们决定地形范围。

**平时（非编辑模式）**

| 参数 | 说明 |
|---|---|
| 显示控制点 | 平时是否显示稀疏控制点，默认开 |
| 控制点间隔 | 每隔 N 个采样放一个点，默认 8。128 采样 → 16 个点 |
| **平滑拖动** | **默认关**。关着时每个点只影响自己；打开后拖一个点会带动左右邻居 |
| 平滑影响范围 | 只在「平滑拖动」打开时生效，带动左右各 N 个邻居，默认 3 |
| 显示边界方块 | 绿/青/橙那几个方块的总开关。专心拖控制点时关掉，免得碍事 |

**默认每个点独立**：拖一个点只改它自己的高度，不碰别的点。
想要"拖一个点周围跟着平滑起伏"的手感，才打开「平滑拖动」。

**两条拾取规则（避免方块挡住点）**

1. **控制点永远优先于方块。** 鼠标同时靠近一个点和一
   个方块时，选中的一定是点。方块只是辅助手柄。
2. **方块的位置跟着点走。** 绿色方块放在左右边折线的**实际中点**上
   （沿长度取中点），所以给边加点、拖动之后方块会跟着移动，不会飘到形状内部。

一次拖动只产生一步 Undo，Ctrl+Z 能整段撤销。编辑模式会记住，切换选中物体再回来还在。

**碰撞体**

- 只有**一个**开关：「生成碰撞体」。打开就是**整个体块**的闭合轮廓
  （地表 + 右链 + 底边 + 左链），和渲染用的是同一套点，从任何方向都挡得住。
- 「碰撞体垂直偏移」：碰撞边缘和视觉边缘对不上时用它推开。
- 「碰撞体采样间隔」：每隔 N 个采样点取一个，只有地形特别长时才调大。
- 旧版本那套「地表一条开链」的 `EdgeCollider2D` 已经删了 —— 那条链没有内外之分，
  从下方、侧面都能穿进去，地表一有折还会在折的地方断开（表现是"走一半突然没碰撞"）。
  场景里残留的旧组件会被自动禁用，不销毁。
- 想看碰撞体到底画到哪儿：打开视口**右下角**的「碰撞体」开关。

**API**

```csharp
var terrain = GetComponent<LDK2DHeightmapTerrain>();

terrain.Generate();                       // 按当前参数用噪声生成（会清掉四条边的控制点）
terrain.Flatten();                        // 拍平
terrain.DestroyCircle(localPos, 2.5f);    // 炸出一个坑
terrain.RaiseCircle(localPos, 1.5f);      // 堆一坨土
terrain.SampleHeight(localX);             // 插值取地表高度
terrain.SampleWorldPoint(localX);         // 世界坐标地表点

terrain.InsertSample(10);                 // 在索引 10 处插入一个采样点
terrain.RemoveSample(10);                 // 删除索引 10 的采样点
terrain.Subdivide();                      // 整体细分，点数 → 2n-1
terrain.Simplify();                       // 整体简化，点数约减半

float[] h = terrain.Heights;              // 直接改数组
h[10] = 5f;
terrain.Rebuild();                        // 改完重建
```

> **`Generate()` 会重置形状。** 它是一块新地形，所以四条边上的控制点和横向偏移
> 都会清空 —— 否则会出现"地表是新的、边还是旧的"那种半新半旧的状态。
> 只想换密度（改 `sampleCount`）不会清边：那条路走的是内部的高度重铺，边上的点保留。

`Heights` 是序列化的，所以编辑器里生成好的地形在进入 Play 模式后还在。

**挖坑原理**：地形是地表线以下的实心区域。爆炸圆在该列的圆底高度若低于当前地表，
就把地表压到圆底 —— 也就是"地表只降不升"，正好是弹坑的形状。

坑底的下限取的是**渲染实际用的那条底边**（雕过的底边折线、逐点底部轮廓、或 `bottomY`），
所以浮空岛上炸坑不会把地形打穿到下面的空气里。

**`SampleHeight` 的前提**：正常情况地表在 X 上是递增的，走二分查找。但自由 2D 拖动
允许你把某个点的 X 拖过它的邻居，那时"这个 X 的高度"本身就有歧义了 ——
这时它退化成线性扫描，取所有跨过该 X 的区间里**最高**的那段（玩家实际会站上去的地表）。
所以横向拖歪不会让寻路/刷怪拿到一个离谱的高度，但**地形本身也会跟着折**，
该把点拖回去还是得拖回去。

## 资源替换：灰盒交给美术之后，贴图怎么上去

### 先纠正一个几乎人人都会踩的误解

**美术没法把 sprite 拖进地形的材质槽。** 地形是 `MeshFilter` + `MeshRenderer`，
材质槽（`Element 0`）只吃 **Material**，不吃 Sprite —— Sprite 是给 `SpriteRenderer`
用的，两者是不同的渲染路径。所以"把 sprite 覆盖到灰盒上"这个说法在 Unity 里没有
对应的操作。

正规做法只有两条，取决于要平铺还是要拼件：

| 做法 | 操作 | 适合 |
|---|---|---|
| **换材质** | 建一个 Material，贴图塞进 Base Map，拖到 `Element 0` | 内部大面积平铺 |
| **加拼件** | 在地形下加子物体，各挂 `SpriteRenderer`，然后关掉地形的 `MeshRenderer` | 边缘、端点、凸角 |

两条可以同时用：地形本体负责内部填充，子物体负责轮廓装饰。**都不是"先盖住再删壳"** ——
壳（Mesh + 碰撞体）必须留着，碰撞体和 `SampleHeight` 都挂在它身上。

### 那个 `LDK2D (Universal R P...)` 材质是什么

`Element 0` 里那个不是项目资产，是 `LDK2DMeshUtil.EnsureMaterial()` 在运行时**自动生成的内嵌材质**，
只存在于内存/场景里。它没有贴图槽可以点，也没法在 Project 里找到。

要交给美术，必须换成一个真正的材质资产：

1. Project 里右键 → `Create → Material`（URP 2D 项目选 `Sprite-Lit-Default`
   或 `Sprite-Unlit-Default`，看要不要吃 2D 光照）
2. 把贴图拖进材质的 `Base Map`
3. 材质拖到地形的 `MeshRenderer → Element 0`

> **交出去之前把「应用颜色」关掉。** 打开状态下，组件会通过 `MaterialPropertyBlock`
> 每帧把 `color` 字段刷进渲染器，美术在材质里调的色调会被直接盖掉，看起来像"材质改了没反应"。

### 两种 UV 模式

| | 平面映射 `Planar` | 沿曲面平铺 `SurfaceTiling` |
|---|---|---|
| U | 世界 X × `uvScale` | **沿地表累计的弧长** × `uvScale` |
| V | 世界 Y × `uvScale` | **垂直地表往下的距离** × `uvScale` |
| 斜坡上的表现 | 贴图被拉长 `1 / cos(坡角)` 倍 | 密度处处一致，不被拉长 |
| 代价 | 零成本 | `Rebuild` 时多一次 O(n) 遍历 |
| 适合 | 接近平坦的地面、纯色材质 | 有陡坡、悬崖、波浪地形 |

默认是 `Planar`，所以老场景的观感和以前完全一样，不会因为升级插件而变样。

`SurfaceTiling` 里 V 用的是「垂直厚度 × cos(坡角)」，不是直接拿垂直厚度 —— 因为
纹理空间是贴着坡面走的，垂直于坡面的厚度才是纹理上真正被消耗的那一段。少了这个
`cos`，陡坡上的 V 方向会被压扁，纹理在坡底和坡顶对不齐。

### `uvScale` 到底填多少

**`1 / uvScale` = 贴图重复一次所跨的世界单位数。** 反过来算：

```
uvScale = 1 / 你希望贴图重复一次的距离
```

| 想要的重复距离 | `uvScale` |
|---|---|
| 1 世界单位 | 1 |
| 2 世界单位（默认） | 0.5 |
| 4 世界单位 | 0.25 |
| 8 世界单位 | 0.125 |

如果贴图是 256px、PPU 设 256，那它本身就是 1×1 世界单位 —— 想让它一格贴一格不缩放，
`uvScale` 就填 1。

### 没有贴图的时候怎么验证

勾上 **「显示 UV 网格」**，Scene 视图会沿地表每 `1 / uvScale` 个世界单位画一根短刻度
（只往下画 0.8 单位，免得挡住轮廓和控制点）。

判读方法：

- **平地上刻度等距** → 基本对了，但还不能证明什么，平面映射在平地上也是等距的
- **斜坡上，沿着坡面量，刻度仍然等距** → 这才是弧长映射生效的证据
- **斜坡上刻度变稀** → 还在平面映射（U 跟着世界 X 走，坡越陡越稀）

上限 2000 根，`uvScale` 填得极小时不会把视口拖死。

### 公开 API

```csharp
float len = terrain.SurfaceLength;        // 地表总长（世界单位）
float d   = terrain.ArcLengthAt(12);      // 第 12 个采样点距起点多远
float cos = terrain.SlopeCosAt(12);       // 该点的 cos(坡角)，1 = 平地
```

`SurfaceLength` 可以直接拿来算"这张贴图沿地表要铺几次"，也是拼件按世界单位放置时的
分母。三个值都在 `Rebuild()` 里重算，不需要手动调。

### ⚠️ 地形的 `Transform.Scale` 必须是 1

UV 是按**世界单位**算的，但 `Scale` 会把整个网格连同 UV 一起缩。`Scale = 0.29` 的地形，
贴图密度会变成 0.29 倍（纹理被挤密），挂在下面的子物体 sprite 也跟着缩成 0.29，
碰撞体精度也会掉。

**用「采样间距」控制地形世界尺寸，不要用 `Scale`。** 反算公式：

```
spacing = 期望的世界宽度 / (采样点数量 - 1)
```

比如要一块 20 单位宽、129 个采样点的地形，`spacing = 20 / 128 = 0.15625`，
`Scale` 保持 1。

### 这一版的边界

能做的：整块地形换一个平铺材质，密度均匀，接缝可校验。

还不能做的：**端点、凸角、凹角不会自动换图**。纯平铺在转角处只会把纹理硬折过去，
看起来是"一张壁纸糊在悬崖上"。要做到"顶面一套图、侧面一套图、转角一块拼件"，
需要模块化拼件 —— 那是下一个版本的内容（sprite list + 角度区间 + 沿弧长按世界单位
放置 + 凸角/凹角特判），弧长这套地基已经铺好了，拼件和 UV 共用同一份数据。

## 实时编辑（边跑边改，退出后留得住）

测试阶段 · 什么都没选的面板里有一个「**实时编辑**」勾选框。勾上之后：

1. 按 Unity 自己的 Play 键（这个开关**不进 Play**，编辑器已经有播放/暂停/停止了）
2. 在 Scene 视图里拖地形点、改 Inspector 参数、造敌人 / NPC / 奖励点
3. 按停止 —— 改动**写回场景**，一个 Ctrl+Z 能把整次回写撤回

不勾的话，Play 里连地形手柄都不画：视口干净，专心跑图。

**为什么需要它**：Unity 进 Play 时给整个场景拍一张快照，退出时按快照恢复。
所以 Play 里的改动全被倒带。要"退出后还是 Play 里那个样子"，三件事都得补：

| Play 里做了什么 | Unity 退出时 | 工具补的动作 |
|---|---|---|
| 改（拖点 / 改参数 / 移动） | 数据被抹回进 Play 前 | 把 Play 里的数据写回去，再 `Rebuild()` |
| 删 | 物体**复活** | 再删一次 |
| 增 | 物体**销毁** | 按序列化数据重建 |

管两种东西：`LDK2DHeightmapTerrain` 和 `LDK2DTestActor`。标记笔迹本来就能在 Play 里画、
也本来就会抢救（`LDK2DMarkupTool` 那套），不重复处理。

**几个行为细节**

- **没动过就不写回。** 退出时先比一遍序列化字符串，一模一样就跳过 ——
  否则每次按 Play 都会把场景标脏，人什么都没干却要吃一个「有未保存的改动」提示。
- **开关以退出那一刻为准。** 进 Play 时的名单是无条件拍的，所以中途打开开关也能写回；
  中途关掉就不写回。
- **Play 里改的 Inspector 参数也会回写**，和拖点走的是同一条路（同一个序列化字符串）。
- 重建出来的地形 / 标记落在**场景根**，不还原原来的父物体层级。地形和标记本来就该在根上
  （地形有缩放，标记挂上去会跟着缩），实际碰不到。

**已知边界**

- **Play 里切换场景 = 整次不写回。** 进 Play 时会记下当前激活场景的路径，退出时对不上就
  直接放弃 —— 换了场景之后基线那批物体已经不是同一批，按 id 对齐会把**原场景的地形**
  判成"被删了"再删一次，那是直接毁关卡。宁可这次不写回。
- Play 里**新建**一个东西、又在 Play 里**删掉**它：什么都不发生（它本来就不该留下）。

## 测试角色

菜单 `GameObject → LDK2D → 创建测试角色`。出来一个方块，按 Play 就能跑能跳，
用来在改完地形后**立刻**回答"这个坑跳得过去吗"。

**它不依赖任何美术资源。** 没指定 sprite 时会自己生成一张 16×16 的白色方块
（PPU 16，正好 1×1 世界单位）和一个无摩擦 `PhysicsMaterial2D`，都是
`HideAndDontSave`、整个进程共用一份。想换成正式角色，把 sprite 拖进
`SpriteRenderer` 就行，组件不会再覆盖它的颜色。

| 参数 | 默认 | 说明 |
|---|---|---|
| 移动速度 | 7 | 水平最大速度（世界单位/秒） |
| 加速度 | 90 | 地面加速度，越大越跟手 |
| 空中操控 | 0.6 | 空中加速度相对地面的比例 |
| **跳跃高度** | 2.6 | **填世界单位，不是初速度** |
| 土狼时间 | 0.1 | 离开地面后仍可起跳的宽限 |
| 跳跃缓冲 | 0.12 | 落地前提前按跳跃，落地瞬间生效 |
| 下落重力倍率 | 1.8 | 大于 1 手感更干脆，不会飘 |
| 地面层 | 全部 | 哪些层算地面 |
| 最大坡度 | 50° | 超过这个角度不算站得住 |

跳跃高度填世界单位（内部按 `v = sqrt(2gh)` 反推初速度），是因为要跟关卡里的
**间距**直接对比：地形上量出这个坑 3 单位宽、落差 1.2 单位，那 `jumpHeight`
就调成 1.5 试一把，比反复试初速度数值快得多。

地面判定用的是 `Rigidbody2D.IsTouching` + 接触法线角度过滤，不是向下打射线。
好处是贴着墙时不会误判成落地，斜坡上也能正确站住 —— 射线检测在这两种情况下都会出错。

> **它不是成品角色控制器。** 只有左右移动、跳跃、土狼时间、跳跃缓冲四件事。
> 真实项目请换掉，这里的作用是把地形验证出来。

## 占位标记（敌人 / NPC / 奖励点）

测试阶段、**什么都没选**的时候，左上角面板里有这三行：选类型 → 点「创建」，
当前 Scene 视图中心就多一个方块。

| 种类 | 颜色 | 尺寸 | 类型 | 碰撞 |
|---|---|---|---|---|
| 敌人 | 红 `0.85 0.25 0.25` | 0.8 × 0.8 | 巡逻 / 飞行 / 射击 / 静止 | 实心 |
| NPC | 蓝 `0.30 0.62 0.95` | 0.7 × 1.05 | 对话 / 商贩 / 任务 | 实心 |
| 奖励点 | 金 `0.95 0.78 0.22` | 0.45 × 0.45 | 金币 / 血包 / 存档点 | 触发器 |

**碰撞**：敌人和 NPC 是实心的，走过去会被挡住；奖励点是 `isTrigger`，人不被挡 ——
将来拾取判定就挂在这上面。

**敌人的行为**（`LDK2DTestEnemy`，**只在 Play 模式动**）：

| 类型 | 行为 |
|---|---|
| 巡逻 | 地面行走，前方撞墙**或前方没有地面**就转身 —— 不会自己走下悬崖 |
| 飞行 | 不受重力，在出生点左右 `flyRange` 范围内往返，带一点上下浮动 |
| 射击 | 站着不动，每 `fireInterval` 秒朝角色发一颗子弹 |
| 静止 | 不动，只有碰撞 |

撞到角色会把人弹开（`knockback`，默认 9）。项目还没有血量系统，所以「受伤」暂时
只表现成击退 —— 够用来验证"这个敌人放的位置对不对"。

子弹（`LDK2DTestProjectile`）是触发器，飞 4 秒或者撞到东西就消失；撞到角色同样击退。
子弹会穿过其他敌人和占位标记，不会卡在自己身上。

**NPC 和奖励点没有任何逻辑** —— 对话、商贩、拾取都还没做，它们只是标记。

和测试角色一样不依赖美术：自己生成 16×16 白色 sprite（PPU 16，1×1 世界单位），
按种类染色。

几个刻意的决定：

- **不挂父物体**。地形常有 0.06 ~ 0.3 的缩放，挂上去标记会跟着缩成一点
- **位置取 Scene 视图中心，Z 手动归零**。2D 视图的 `pivot.z` 实测在 9.8 左右，
  照抄会把标记甩到相机前面去
- **重名自动加序号**（`敌人·巡逻 2`），Hierarchy 里不会一排同名分不清
- 选中的类型存 `EditorPrefs`，重启 Editor 还记得上次选的
- 创建后**不选中**新物体，只 `PingObject` 闪一下 —— 选中会让地形面板立刻消失

想加自己的类型，改 `LDK2DTestActor.TypeTable` 里对应那一行就行（三行分别对应
敌人 / NPC / 奖励点）。

> **依赖旧版 Input**（`Input.GetAxisRaw` / `GetButtonDown`），因为这个项目
> `Active Input Handling` 是 Input Manager。换成新输入系统的话，改 `Update()` 里那四行即可。

## 性能清单

- 别给每个 Tile 挂 Collider。Tilemap 用 `TilemapCollider2D` + `CompositeCollider2D`，
  并勾上 `Used By Composite`，几百个格子会合并成几个多边形。
- 地形碰撞体是**整块实心**的 `PolygonCollider2D`（和网格同一套点），不要再给地形单独挂
  `EdgeCollider2D` —— 两套重叠等于双份开销，而且开链从下方能穿过去。
- 碰撞体顶点数要控住。不规则轮廓先做抽稀（`colliderStride` 或 Douglas-Peucker）。
- 角色卡在接缝上：`CompositeCollider2D` + 胶囊碰撞体 + 调 `Contact Offset`。
- 重建 Mesh 是 CPU 操作，别每帧对大地形调用。改数据后重建一次即可。
  重建用的缓冲区是**组件持有、反复复用**的（`LDK2DMeshBuffers`），稳态下零托管分配；
  拓扑没变时还会跳过索引和法线的重传。真正的开销剩下 `PolygonCollider2D.SetPath`
  —— 它要重建物理形状，所以**拖动时碰撞体只每 100ms 更新一次**（视觉网格仍是每帧），
  松手时补最后一次。想关掉这个降频就把 `InteractiveColliderInterval` 改成 `0f`。
- 大地形还嫌卡：把 `colliderStride` 调大（碰撞轮廓抽稀），或减少采样点。
  碰撞体顶点数是 `SetPath` 成本的直接乘数。

## 选型

| 需求 | 方案 |
|---|---|
| 平滑起伏、手绘轮廓、要好看 | Sprite Shape（路线 A） |
| **地形中间要挖洞（隧道 / 洞穴）** | **LDK2DPolygonMesh（路线 B）** |
| 随机生成、固定种子、可破坏 | LDK2DHeightmapTerrain（路线 C） |
| 大块地形、平台、悬崖，四条边都要能加点 | LDK2DHeightmapTerrain（路线 C） |

两条路线的边界很清楚：**需要"环"这种拓扑（洞）→ B；其余都用 C。**
C 的四条边都能加点、能拖成任意形状，比 B 多出噪声生成和可破坏两个能力。

## 排障：视口里的工具不见了

**先别怀疑文件丢了。** 正常情况下左下角和左上角各有一块，总在：

| 位置 | 内容 | 什么时候在 |
|---|---|---|
| 左下角 | 关卡设计 + 阶段选择器 | 永远 |
| 左上角 | 阶段工具 / 层级颜色 / 创建按钮 | 永远，内容随选择变 |

如果左下角那条都没有，多半是 `SceneView.duringSceneGui` 的注册没跑起来 ——
那个注册挂在 `LDK2DSortingOrderToolbar` 的 `[InitializeOnLoad]` 上，
保存任意脚本触发一次重编译即可恢复。

如果只有左下角、左上角空了：说明当前选中的物体**没有渲染器**。
那种选择下会故意保持安静，不会弹「创建地形」的提示。

如果左上角面板位置别扭：它固定在 `x ≈ 2.6 行高`、`y ≈ 2.4 行高`，
也就是 Unity 自带竖排工具条的右边。想挪位置改 `LDK2DSceneToolbarLayout.Panel()`。

> 早期版本里地形工具栏贴在**视口底部**、只在编辑模式下出现，
> 现在拆成两个角：选择器在左下角（永远在），工具在左上角。
> 编辑模式只决定画不画控制点，不影响工具本身。

### 恢复步骤

| 症状 | 处理 |
|---|---|
| 场景里根本没有地形物体 | 左上角面板的 [创建高度场地形]，或菜单 `GameObject ▸ LDK2D ▸ 创建高度场地形` |
| 有物体但看不到控制点 | 选中它，Inspector 里点「进入编辑模式」 |
| 物体上显示 `Missing (Mono Script)` | 脚本 GUID 对不上，见下 |

### 如果物体显示 Missing (Mono Script)

场景里记的是脚本 GUID，脚本文件被删或 `.meta` 被重新生成，引用就断了。当前 GUID：

| 文件 | guid |
|---|---|
| `Scripts/LDK2DHeightmapTerrain.cs.meta` | `611f7509e735cf245ac346d37347e200` |
| `Scripts/LDK2DPolygonMesh.cs.meta` | `14e601de5bd66804cafb4f793c449231` |
| `Editor/LDK2DToolsEditor.cs.meta` | `1c32c5ef3e55b9e4cadafbd865bda989` |

`.meta` 和 `.cs` 必须成对存在。只拷 `.cs` 不拷 `.meta`，Unity 会生成新 GUID，
原来场景里的引用就全断了。

### 崩溃后找回没保存的场景改动

**基本找不回来，别指望。** Unity 2022.2+ 在 `Preferences ▸ General ▸ Auto Save`
有个自动保存开关，但它对场景改动的可靠性很差；整机断电 / 蓝屏 / 强杀进程
也不会生成 `Temp/__Backupscenes/`（那个只在 Unity 自己捕获异常退出时才有）。

实测过一次崩溃：项目里既没有 `Temp/__Backupscenes/`，也没有 `Temp/Autosave/`，
场景文件停在崩溃前最后一次手动保存的状态 —— 崩溃前新建但没保存的物体全部丢失。

**保险做法**：把项目放进 Git（`Library/`、`Temp/` 写进 `.gitignore`），
或者至少养成改完就 Ctrl+S 的习惯。编辑器脚本改坏了也能靠 Git 一键回退。

## 四条边怎么加点

四条边的命中判定都走 `FindNearestSegment`，但**加点存在哪不一样**：

| 边 | 加点存在哪 | 会不会动到别的边 |
|---|---|---|
| 地表 | 采样数组（`InsertSample`） | — 就是它自己 |
| 右边 | `RightEdge` 独立折线 | 不会 |
| 左边 | `LeftEdge` 独立折线 | 不会 |
| **底边** | `BottomEdge` 独立折线 | **不会** |

Shift+点哪条边，点就加在哪条边上，其他边一概不动。

### 底边为什么需要一条独立折线

以前地表和底部**共用同一套采样下标**（`_heights[i]` 和 `_bottomHeights[i]` 用的是同一个 `i`），
所以往底边加点只能走 `InsertSample`，结果就是：

1. 地表凭空多出一个点；
2. `spacing` 重算（总宽保持不变 → 每段间距变小），**地表所有点的 X 跟着挪位**，
   形状整体变形。

用户看到的就是"我点底边，上面也跟着变了"。

现在底边有自己的折线 `BottomEdge`（本地坐标，**右 -> 左，含两个角点**）：

- **空** = 老行为：用 `bottomY` 那条平直线，或开了「底部独立轮廓」之后的逐点数据；
- **有点** = 它就是底边的全部，渲染（`BuildOutline`）和碰撞（`BuildColliders`）都从它走。

**第一次点底边时**会先用当前底边把折线种下来（`SeedBottomEdgeIfEmpty`），形状零变化，
然后才插点。所以 `sampleCount` / `spacing` / `originX` / `_heights` / `_topOffsetsX`
**一个都不动**，底边只是多了一个点，可以立刻拖它塑形。

一次 Ctrl+Z 撤销。

> `HasStraightSides` 在有底边折线时返回 false，网格自动从三角带切到耳切。
> 这是必须的：三角带按"地表点与底部点逐点对齐"铺，折线的点数和地表脱钩后铺不了。

### 三条曾经"看得见、点不中"的边（已修）

| 边 | 曾经的问题 |
|---|---|
| **底部** | `if (bottom == null) continue;` —— 没开「底部独立轮廓」时整条底边被跳过，Shift+点击毫无反应 |
| **左边** | 判定用的折线拿 `originX` 当左上角，画出来的却是 `TopXAt(0)`。**横拖过最左侧地表点之后**两者差一个 `TopOffsetX(0)`（实测 2.5 单位 ≈ 60px，远超 14px 命中半径），这条边就"看得见、点不中" |
| 右边 | 一直正常 —— 它用的是 `TopXAt(last)`，本来就带偏移 |

排查这类问题先看两个值：Inspector 里的 `_topOffsetsX[0]` 是不是 0、
「底部独立轮廓」开没开。

### 其他操作

| 你的目的 | 怎么做 |
|---|---|
| 底边整体上下移 | 用橙色方块（「底边整体」），不用加点 |
| 底边加点塑形 | Shift+点底边 → 拖紫色点 |
| 删底边上的点 | Ctrl / Cmd + 点紫色点 |
| 所有边恢复成直线 | Inspector / 工具栏的「**清空边加点**」 |
